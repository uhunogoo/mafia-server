# 09 — Ping anti-spam model

Type: grilling
Status: open
Blocked by: 04

## Question

Як запобігти спаму пінгами, не зламаючи spirit of the game?

З регламенту маємо тверде обмеження: «одне активне питання на гравця». І таймаут 15-20с на відповідь. Після смерті пінги вимкнені.

Але потенційно гравець може:

- спамити `підозрюю X` по 50 разів за день
- переключатись між цілями швидко
- питати «яка думка?» одного гравця, відповідь → знову питати того самого

Потрібно вирішити:

1. **Ліміти на відправлення**:
   - Чи є ліміт `pingsPerPlayerPerDay` (наприклад, 20)?
   - Чи є ліміт `pingsPerTargetPerDay` (наприклад, 5)?
   - Чи є rate-limit на рівні `pingsPerPlayerPerMinute` (наприклад, 10)?
   - Чи достатньо самого «1 active question per player» + 15-20s timeout?

2. **Ліміти на ОТРИМАННЯ (адресат)**:
   - Скільки активних ping-ів може висіти на адресаті? 1 чи можна мати N, але відсортовані?

3. **«Хочу слово» ping**: це запит до хоста. Чи має ліміт (наприклад, 1 раз за день, чи тільки під час BALAGAN)?

4. **«+1 / довіряю / не довіряю» під час чужої промови**: чи має взагалі ліміт? Це жести в реальному часі, швидкі реакції — спам неможливий через те, що є лише 1 промовець.

5. **Як зберігати лічильники**: чи в state (`player.pingsSentToday: number`), чи в пам'яті RoomHandler (без state-реплікації)?

6. **Що відбувається при перевищенні**: мʼяка відмова (`error: "ping limit reached"`)? Чи тверда (ігнор)?

## Out of scope

- Клієнтський throttle (на сервері валідація)
- Поведінка самого UI (відключення чіпів)

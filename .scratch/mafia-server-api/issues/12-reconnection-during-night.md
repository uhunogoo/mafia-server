# 12 — Reconnection-during-night policy

Type: grilling
Status: open
Blocked by: (none)

## Question

Як сервер обробляє дисконнект гравця під час нічного вікна дії?

В `src/modules/auth.ts` вже є `RECONNECTION_TIMEOUT = 30` секунд. Потрібно узгодити з нічними вікнами.

Сценарії:

A. **mafia player відключився під час NIGHT_MAFIA**:
   - Сервер відкрив вікно, mafia players мають тапати ціль
   - Гравець відключився — чи його голос (якщо вже віддав) враховується?
   - Чи чекати 30с reconnection?
   - Якщо не повернувся — пропускаємо його голос; якщо повернувся — даємо віддати

B. **don відключився під час NIGHT_DON_CHECK**:
   - Don не встиг перевірити → цієї ночі нема don check
   - Чи все одно продовжувати далі (sheriff, doctor)?
   - Чи сервер пропускає фазу автоматично потай?

C. **sheriff/doctor відключився під час їх вікон**:
   - Схоже на don — пропуск перевірки/лікування

D. **dead player reconnect** (помер удень, намагається зайти вночі):
   - Має бути заблокований (state.isAlive = false → onAuth rejects)

Потрібно вирішити:

1. **Чи блокує сервер вікно дії, якщо дисконект?** Чи продовжуємо без гравця?
2. **Чи скасовує вже зібрані targets від дисконектованого гравця?** (Рекомендація: ні — його голос уже в `nightAction.targets`)
3. **Як сервер сповіщає хоста** про дисконект під час ночі? Через окреме повідомлення `playerDisconnected(sessionId, role)`?
4. **Чи переривається вікно при дисконнекті?** Ні — сервер продовжує чекати in-вікна від решти, дисконектнутий — out.

5. **Вплив на нічний результат**: якщо mafia втратила одного гравця, решта голосують. Якщо дон відключився — `donLog` не отримує запису.

## Out of scope

- Сам reconnection mechanism (вже в `auth.ts`)
- Reconnect під час дня (використовує існуючий механізм)
